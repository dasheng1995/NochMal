# 德语单词极速刷词 — Android App 产品需求文档（PRD）

> 版本：v0.4  
> 日期：2026-11-25  
> 状态：草案（待确认后进入开发）  
> 平台：**Android App（个人自用，本地运行，无自建服务器）**  
> 目标设备：三星 S24 等，兼容 **Android 16**（建议 minSdk 覆盖 Android 12+）  
> 数据源：`English-Deutsch (Sorted by Frequency).apkg`  
> UI 参考：`a1-b2/` 下 JPG（`单词含义选择.jpg` / `选对.jpg` / `选错.jpg` / `单词释义.jpg`）

---

## 1. 产品目标

面向中文用户，提供**高吞吐、多遍覆盖**的德语词汇学习工具。核心不是「一张卡间隔拉很长」，而是：

1. **A1 / A2 / B1 / B2 为最高层词库**，彼此隔离；用户可先只背某一个（如只背 A1）；
2. 单个词库内再拆成多个 **List**，按七日滚动反复刷；该库刷满 N 遍后，再自行选择进入其他词库；
3. **每个词库独立进度**（遍次、List、斩/未看/模糊/不会统计互不影响）；
4. 支持 **斩（Easy）雪藏**；每词库提供 Easy / 未看过 / 模糊 / 不会 的统计与列表入口；
5. 刷词 UI 对标参考 JPG：图文选项卡、对错反馈、释义详情页；
6. **安装轻量 App 本体**，词库（含音频+强压缩配图）以**独立词库包导入**，按需安装 A1/A2/B1/B2。

成功标准（首期）：

- 可在 Android 手机安装 App，并成功导入至少一个词库包后开始刷词；
- 用户可任选一个已导入的顶级词库开始，且不会与其他词库进度串扰；
- 单次会话可稳定完成数百词量级的选择练习（离线可用）；
- 当前词库内每个未斩词在冲量阶段按计划完成约 N 遍（默认 6）曝光；
- 每词库可查看四类统计并进入对应词表；
- 释义与例句翻译同时提供**中文 + 英文**。

## 2. 范围

### 2.1 In Scope（MVP）

- **Android App 本体**（侧载 APK/AAB 即可，不上架也可）
- **词库导入式分发**：App 不含完整词库媒体；用户从文件选择器导入预构建词库包（建议按 A1/A2/B1/B2 分包）
- 构建流水线从 apkg 生成词库包（词条 + 音频 + 强压缩配图 + 中英释义）
- 词库内 List 切分与冲量刷词；**词库间进度完全独立**
- 每词库统计入口：**Easy（斩）/ 未看过 / 模糊 / 不会**（可点进列表）
- 选择题刷词主流程（看词选义）
- 答对 / 答错反馈态
- 单词详情/释义页（继续学习入口）
- 「斩」雪藏已会词（仅作用于当前词库）
- List 日程与遍次推进（七天压缩曲线可配置）
- **本地进度存储**（SQLite / DataStore；可导出备份文件）
- 单词发音、例句发音（复用 apkg 音频，可再压缩码率）
- 释义/例句中英双语（中文由 AI 翻译生成并写入词库包）
- **选择题强制配图**：每词一张贴合词义图（AI/网络，**禁止源包图**），**尽量压缩体积**

### 2.2 Out of Scope（首期不做）

- 自建服务器 / 云同步账号体系
- 网页版 / PWA（可作为远期复用）
- 应用商店上架与付费
- 完整社交 / 排行榜
- 手写输入默写为主模式（可留入口）
- 复杂 AI 对话陪练（底部 Ai 按钮可先占位）
- 词根词缀深度引擎、完整变位训练（有数据可只读展示）
- 使用 apkg 内嵌 Image / media 图片作为刷词配图
- App 安装包内置全量 A1–B2 媒体（避免巨型 APK）

## 3. 词库与数据需求

### 3.1 数据源

| 项 | 说明 |
|----|------|
| 文件 | `English-Deutsch (Sorted by Frequency)-*.apkg` |
| 主笔记类型 | `English-Deutsch+` |
| 规模（实测） | 约 **5009** 条主词条；卡片约 10018（含生产向牌面，产品侧按「词条」而非 Anki 卡片数计） |

### 3.2 信息架构：顶级词库 → List → 词

```text
App
 └─ 词库（最高层，四选一进入）
     ├─ A1
     ├─ A2
     ├─ B1
     └─ B2
         └─ 仅在「当前词库」内：
             ├─ List 1 … List N   ← 反复刷的单位
             ├─ 独立进度（遍次 / 日程 / 完成度）
             └─ 独立统计（Easy / 未看过 / 模糊 / 不会）
```

学习路径约定：

1. 用户先进入某一个顶级词库（例如只背 **A1**）；
2. 该词库内的词按词频切成多个 List，按冲量曲线在**本库内**反复刷；
3. 本库达到目标遍数 N（默认 6）或用户主观完成冲量后，回到词库总览，**再选择** A2 / B1 / B2；
4. **不强制**按 A1→A2→B1→B2 解锁；允许随时切换词库，但切换后看到的是该库自己的进度，互不合并、不互相占用今日任务。

### 3.3 词库划分规则（强制）

按 apkg 中的 **Level 字段** 与 **同名标签** 划分，二者应一致；导入时以字段 `Level` 为准，标签作校验。

| 顶级词库 | 源 Level 字段 | 源标签 | 约词数 |
|----------|---------------|--------|--------|
| A1 | `A1` | `A1` | ~655 |
| A2 | `A2` | `A2` | ~590 |
| B1 | `B1` | `B1` | ~1826 |
| B2 | `B2+` | `B2plus` | ~1938 |

规则：

1. 只收录主笔记类型 `English-Deutsch+`；
2. `B2+` / `B2plus` **映射为产品词库 B2**（界面展示「B2」）；
3. 一词仅属一个顶级词库；冲突时以 `Level` 字段为准并记日志；
4. 词库内默认按 `Rank`（词频序）排序，保证「高频先刷」；
5. List 只存在于词库内部，**不得跨词库组 List**。

> 说明：四个词库总量约 5000，不等于「每库刚好 500×4」。每个词库各自按实际词数动态切分 List（默认 4 个 List），不必写死 500。

### 3.4 源字段映射

| 源字段 | 用途 |
|--------|------|
| Rank | 词频排序、展示「高频序」 |
| Word | 德语词形（含冠词信息时需解析，如 `der, -`） |
| IPA | 音标 |
| Part-of-Speech 1/2/3 | 词性；名词性别可能落在 pos（der/die/das） |
| Definition 1/2/3 | **英文释义**（源数据） |
| German 1/2/3 | 德语句例 |
| English 1/2/3 | 例句英文翻译（源数据） |
| WordAudio | 单词音频 `[sound:*.mp3]` |
| SentenceAudio1/2/3 | 例句音频 |
| Level | CEFR 等级 |
| WordFamily | 词族（详情页可选） |
| Conjugation | 动词变位 HTML（详情页可选） |
| Image | **产品侧忽略**；刷词/详情配图不采用源包图片 |
| Frequency | 可存档，首期可不展示 |
| tags | 等级 + 词性标签（verb/adj/der/die/das…） |

### 3.5 需 AI 生成并落库的内容（中英双语策略）

源包释义与例句翻译以**英文**为主。产品要求：

| 内容 | 英文 | 中文 |
|------|------|------|
| 单词释义（每义项） | 使用源 `Definition N` | **AI 翻译生成** `Definition_ZH_N` |
| 例句翻译 | 使用源 `English N` | **AI 翻译生成** `Example_ZH_N`（由德语句 `German N` 或英译再译，需统一策略） |

推荐策略：

1. 释义中文：`Definition_EN` → AI → `Definition_ZH`（保留词性标签，中文简洁，适合选项按钮短文案）；
2. 例句中文：优先 `German` → AI → `Example_ZH`（比英转中更贴原文）；英文例句继续展示源 `English`；
3. 生成结果写入静态词库 JSON/SQLite，**运行时不再实时调 AI**（保证刷词速度与稳定性）；
4. 需质检抽样：专有名词、冠词、固定搭配、多义词。

界面语言切换（设置项）：

- 选项与释义主文案：`中文` / `English` / `中英对照`
- 默认：`中文`（选项按钮用中文；详情页可中英并列）

### 3.6 媒体资源

**音频（可来自源包）**

- 从 apkg `media` 仅解出 **mp3 音频**，建立 `word_id → word_audio / sentence_audio` 索引；
- 音频播放失败时静默降级，不阻断刷词。

**配图（禁止来自源包，选择题硬性要求；优先压体积）**

1. **强制**：选择题刷词页每道题必须展示一张**符合该词核心含义**的配图；无合格配图的词条不得打进词库包。
2. **来源（构建期完成）**：AI 生成或网络检索；**禁止**使用 apkg `Image` / media 图片。
3. **贴合度**：具象词对具象画面；抽象词用可理解场景隐喻；多义词以义项 1 为主图。
4. **体积压缩（强制策略，构建流水线执行）**：
   - 格式优先 **WebP**（不行再 JPEG）；
   - 最长边建议 **480～720px**（手机刷词足够，勿上 2K 原图）；
   - 质量参数尽量压低，目标单图约 **15～40 KB**（可接受轻微模糊，以能辨认为准）；
   - 去 EXIF、统一调色空间；禁止把未压缩 PNG/原图打进词库包；
   - 音频也可再压：词音/例句音建议单声道、较低码率 mp3（如 48～64 kbps），在可懂前提下减小词库包。
5. **元数据**：`image_path`、`image_source`（`ai`|`web`）、`query_or_prompt`、许可备注。
6. **质检**：抽样看「能不能认出发的是这个意思」；体积抽检超标则重压。
7. 刷词页与详情页共用主义配图。

### 3.6.1 词库包与 App 导入（强制）

采用 **「瘦 App + 外置词库包」**，避免安装包过大，也方便只导 A1 先学。

| 产物 | 内容 | 说明 |
|------|------|------|
| **App 本体 APK** | UI、刷词引擎、进度库、导入/管理词库逻辑 | **不含**（或仅含极少演示词）完整媒体 |
| **词库包** | 单库或打包：词条数据 + 音频 + 强压缩配图 | 建议扩展名如 `.deword` / `.zip`；**一库一包**（`a1.deword` …）优先 |

词库包建议结构：

```text
a1.deword (zip)
 ├─ manifest.json      # level, version, word_count, content_hash
 ├─ words.sqlite|json  # 词条、中英释义、路径索引
 ├─ audio/             # 强压缩 mp3
 └─ images/            # 强压缩 webp
```

App 内流程：

1. 首次打开 → 词库管理页提示「尚未导入词库」；
2. 用户点「导入词库」→ 系统系统文件（下载目录 / 文件管理器中的词库包）；
3. 校验 `manifest`（等级、版本、完整性）→ 解压到 App 私有存储；
4. 导入成功后出现在词库总览（A1/A2/B1/B2 卡片，未导入显示「未安装」）；
5. 支持删除已导入词库（可保留或清空该库进度，需确认）；
6. 支持覆盖导入同 level 新版本词库包（进度是否保留：默认按 `word_id` 尽量保留）。

分发方式（个人用）：电脑构建好词库包 → 传到手机（数据线 / 网盘 / 局域网）→ App 导入。**不依赖自建服务器。**

### 3.7 产品侧词条与进度数据模型（建议）

```text
Word {  // 静态词库，按 level 分属四大词库
  id, rank, lemma, ipa, level(A1|A2|B1|B2),

  wrong_count, last_result?
}
```

## 4. 学习算法与进度（业务规则）

### 4.1 顶级词库进度隔离（强制）

| 规则 | 说明 |
|------|------|
| 独立进度 | A1/A2/B1/B2 各有自己的 List 切分、遍次、日程、统计；**互不共享** |
| 单库专注 | 典型路径：先把 A1 刷满 N 遍 → 再开 A2；中途可切换，但任务与统计始终按「当前词库」计算 |
| 今日任务 | 只生成**当前词库**的 List 任务，不把其他库的词混进同一会话 |
| 完成判定 | 「A1 冲量完成」= 该库未斩词均达到目标遍数 N（或用户手动标记本库冲量结束） |

### 4.2 词状态机（每词库内统计口径）

每个顶级词库必须提供以下 **4 类统计入口**（展示数量，可点击进入该库下的词列表）：

| 状态 | 含义 | 如何进入该状态 | 是否仍进默认刷词 |
|------|------|----------------|------------------|
| **Easy（斩）** | 已完全学会，雪藏 | 用户点「斩」 | 否（除非撤销斩） |
| **未看过** | 从未在刷词中出现 | 初始默认 | 是（作为新词） |
| **模糊** | 见过但掌握不稳 | 用户标模糊 / 或「看过提示后才答对」等产品约定 | 是（优先复习） |
| **不会** | 明确不会或连续选错 | 选错记为不会；可提供「标为不会」 | 是（最高优先短循环） |

补充状态（可计入进度条，但不一定单独做入口）：

- **学习中（learning）**：已看过且最近答对、尚未斩、未标模糊/不会；占用「在学」进度。

统计恒等式（每一词库）：

`总数 = Easy + 未看过 + 模糊 + 不会 + 学习中`

四类入口数量随作答实时更新；列表支持从该状态改回（如撤销斩、把「不会」刷对后降为学习中/模糊）。

### 4.3 阶段划分（针对「当前词库」）

| 阶段 | 目标 | 策略 |
|------|------|------|
| 冲量期（约 7 天/词库） | 本库快速堆遍数 | 本库 List 整表滚动 + 同日睡前第 2 遍 |
| 巩固期（本库 Day 8+） | 省时间、防回生 | 本库「不会/模糊」优先 + 短间隔；Easy 不出队 |

### 4.4 List 切分（仅当前词库）

对**当前顶级词库**（排除已 Easy）：

1. 按 `rank` 排序；
2. 均分为 **N 个 List**（默认 N=4，可配置；随该库词数变化）；
3. 采用「每天新开 List + 滚动复习旧 List」；
4. 每个新 List **当天间隔 6～12 小时必须过第 2 遍**；
5. 换到另一个顶级词库时，重新使用**该库自己的** List 与日程，不重置其他库。

参考节奏（结构模板，词数随词库变化）：

| 天 | 新词 | 复习 | 备注 |
|----|------|------|------|
| Day1 | List1 第1遍 | 睡前 List1 第2遍 | |
| Day2 | List2 第1遍 | List1 第3遍 + 睡前 List2 第2遍 | |
| Day3 | List3 第1遍 | List1 第4 + List2 第3 + 睡前 List3 第2 | |
| Day4 | List4 第1遍 | List2 第4 + List3 第3 + 睡前 List4 第2 | |
| Day5 | — | List1 第5 + List3 第4 + List4 第3 | |
| Day6 | — | List2 第5 + List4 第4 | |
| Day7 | — | List1～4 第6遍总复习 | |

之后间隔可按压缩周期 1/2/4/7 天滚动，或进入本库巩固期。

### 4.5 作答与状态流转

刷词主模式为**四选一选义**。

| 用户操作 | 状态 / 进度影响 |
|----------|------------------|
| 选对 | 若原为未看过/不会/模糊 → 可转为学习中；`pass_count+1`；按本库日程 due |
| 选错 | 标为 **不会**；本会话短循环再见；遍次不盲目 +1 |
| 标模糊（若提供） | 标为 **模糊** |
| 斩（Easy） | 标为 **Easy**；退出本库 List 与默认复习 |
| 撤销斩 | Easy → 学习中或未看过（按是否曾刷过） |

「斩」约束：

- 建议至少见过 1 次后再允许斩；
- 撤销与列表入口挂在**该词库**下，不是全局混合列表。

### 4.6 干扰项（选项）生成

四选一：1 正确 + 3 干扰。

规则建议：

1. 优先**同一顶级词库**、近词性；
2. 避免与正确答案字形/释义过于相同；
3. 选项文案用当前界面语言的短释义（中文模式下用 `def_zh`）；
4. 预生成或运行时采样均可，需保证刷新稳定（同一题选项顺序可打乱）。

## 5. 信息架构与页面

### 5.1 页面列表

1. **词库总览 / 管理页**：A1–B2 卡片（未导入标「未安装」）；**导入词库**、删除词库；已导入的显示进度  
2. **词库主页（单库）**：本库今日任务、List 进度；**四个统计入口**：Easy / 未看过 / 模糊 / 不会  
3. **状态词列表页**：该库某状态词表；撤销斩等  
4. **今日计划页**：仅当前词库当日 List / 遍次、开始刷词  
5. **刷词页（选择题）** ← 对齐 `单词含义选择.jpg`  
6. **答对反馈** ← 对齐 `选对.jpg`  
7. **答错反馈** ← 对齐 `选错.jpg`  
8. **释义详情页** ← 对齐 `单词释义.jpg`  
9. **设置**：语言、每日目标、音效、目标遍数 N、进度导出/导入备份

### 5.2 刷词页（MVP 核心）

视觉与结构对齐参考图：

- 顶栏：返回、上词摘要、会话进度条、更多菜单  
- 主区：**必有配图**（贴合词义，AI/网络图）→ 大号德语词 → 音标 + 发音按钮 → 例句（目标词加粗）+ 例句发音  
- 互动区：**2×2** 四个圆角选项（释义）  
- 底栏图标：换图（可选，仅限预置候选图） / **斩** / Ai（可占位） / 提示 / 发音  

行为：

- 点选项立即判定；
- 正确 → 进入答对态或短暂反馈后下一题；
- 错误 → 错误项标红，同时标出正确项，可点「继续」；
- 点「斩」→ 确认或直接雪藏并下一题。

### 5.3 答对 / 答错态

- 答对：正确项高亮（绿）或侧边正确卡片；可自动跳转下一词或进详情；  
- 答错：错项红底，正确释义标出；用户确认后继续。

### 5.4 释义详情页

对齐 `单词释义.jpg` 的信息密度，德语化改造：

- 词头：德语词、IPA、发音、等级徽章、性别着色（der 蓝 / die 红 / das 绿）  
- 主释义：中英（按设置）  
- Tab 区（有数据才显示）：例句 / 变位 / 词族 / 扩展  
- 例句：德文 + 中文 + 英文（可折叠英文）+ 音频；词头区展示与刷词页相同的主义配图  
- 底栏：斩、继续

## 8. 技术建议（非强制，供排期）

- App：Kotlin + Jetpack Compose，或 Flutter（便于 UI 快速对齐参考图）
- 本地库：Room / SQLite（进度 + 已导入词库索引）
- 媒体：本地文件路径播放；图片用 Coil/Glide 加载 WebP
- 词库构建（电脑侧脚本）：`apkg → 分库包(.deword)`

构建流水线（出词库包，非出巨型 APK）：

1. 解压 apkg，解析 notes，按 Level 分库  
2. 抽取音频并**再压缩码率**  
3. AI 批量中文释义/例句翻译  
4. AI/网络为每词出图 → **强制缩放+WebP 强压缩**  
5. 生成干扰项所需元数据  
6. 按库打包 `a1.deword` / `a2.deword` / `b1.deword` / `b2.deword`  
7. 校验：缺图、缺音、超体积阈值则失败  
8. App 本体单独编译；用户安装 APK 后导入上述包

## 10. 验收标准（摘要）

1. 可在 Android（含 Android 16）安装 App；**未导入词库时不能空刷，导入后可离线刷**；  
2. 词库包可按库导入/删除；APK 本体不含全量媒体；  
3. 配图为强压缩 WebP/JPEG，抽检单图体积与可辨认度达标；来源为 AI/网络，**未使用源包图**；  
4. A1/A2/B1/B2 词数与源标签统计误差 &lt; 1%（B2 对应 B2+）；  
5. **四库进度独立**；每库主页有 Easy / 未看过 / 模糊 / 不会 入口且数量自洽；  
6. 刷词页信息层级对齐参考 JPG；选对/选错明确；斩仅影响本库；  
7. 详情页中英释义/例句按设置可见；连续刷 100 词无明显卡顿或进度丢失；  
8. 进度可导出备份文件。
